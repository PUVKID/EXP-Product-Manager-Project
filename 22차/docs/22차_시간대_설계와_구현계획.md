# 22차 실행 시간대 제한 설계와 구현 계획

2026-10-29 사용자 요청. 20차 2.4.0을 기준으로 22차 2.4.1을 만든다. 21차에는 기존 작업 자료가 있어 보존한다. 사용자 직접 설치용 EXE와 고객 ZIP을 납품한다.

## 요구와 동작

전체 목록 반복에 선택식 매일 실행 시간대를 추가한다. 기본 비활성으로 구버전 동작을 보존하고, 활성화 기본 입력은18:00~24:00이다. 시작 포함·종료 제외이며 24:00은 종료에만 허용한다. 동일 시작/종료는 오류로 안내하고 야간22:00~02:00도 지원한다. 서버 한국 시각을 기존 방식으로 사용한다.

시간 제한과 매시 지정분을 켜면 첫 회차도 지정분까지 기다린다. 17:30/18:02 시작→각18:00/19:00,18:00정각 시작→즉시.18:00~24:00/00분은18~23시만 회차 시작하고 다음 날18시까지 대기한다. 종료 때 새 상품을 시작하지 않고 처리 중 상품은 마무리한다. 대기·일시정지·서버시각미확인 후 복귀 시 현재 허용 시간과 슬롯을 다시 점검하고 지난 시간대를 몰아 실행하지 않는다. N분 간격도 같은 제한을 적용하되 시작 기준 간격을 유지한다. 시간 제한을 끄면20차의 첫회차즉시/간격·정각 동작 그대로이다.

## 화면

기존 흑백 라이트/다크와 나눔고딕Bold700을 따른다. 전체목록반복 선택 때만 실행시간제한 토글,시작/종료를 고르는 둥근 입력과 시간 범위 요약을 표시한다. 표/네이티브 날짜 달력처럼 보이는 입력을 추가하지 않는다. 24:00 명확표기,키보드·포커스·DPI대응,활성실행시편집잠금,저장/재시작복원이 필요하다. 자동등록 요약에도 시간범위를 표시한다.

## 선택과 제약

OS예약을 추가하는 대신 기존Controller와 순수BatchRepeatSchedule에 제약을 넣는다. 기존 단일상품 시간대표와 분리해 그 기능을 바꾸지 않는다. 사용자 명시적 구현 요청과 반복승인생략 선호에 따라 이 설계를 기준으로 진행한다. 인증·한도·원본상품·운영앱·설치는 건드리지 않는다. 연결된Git원격은 현재확인되지않았고 임의공개저장소를생성하지않는다.
