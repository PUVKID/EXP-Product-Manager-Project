원인 확인 및 복구 완료 — 2026-10-13

원인: Codex 도구에서 실행한 프로세스와 Windows 작업 스케줄러에서 독립 실행한 동일 Audit.exe가 같은 HKCU 경로에서 서로 다른 값을 읽었다. 파일 데이터와 TPM 키는 같았다. 도구 환경의 가상화/분리된 레지스트리 보기 때문에 과거 초기화 검증이 실제 Windows 레지스트리를 확인하지 못했다.
실제 Windows의 사용량 복사본에는 이전 기기의 seq=2, 0 사용량/0 추가권 상태가 남았고, 현재 파일은 새 기기의 seq=2 상태였다. 동일 seq의 내용이 다르므로 불일치 오류가 정상적으로 발생했다. PUVKID 이름은 원인이 아니었다.

복구: 일반 Windows 사용자 컨텍스트에서 현재 라이선스 서명과 TPM 기기 소유 증명을 검증했다. 기존 두 상태의 기기/seq/시각과 사용량·추가권·체험 여부를 고정 조건으로 확인한 뒤, 이전 레지스트리 값을 DPAPI 그대로 보관하고 현재 정상 파일과 동일한 보호된 바이트로 실제 Windows 레지스트리 복사본만 맞췄다. 제품 파일/인증키/TPM 등록을 삭제하지 않았고 보안 검사를 완화하지 않았다.

검증: 일반 Windows 컨텍스트의 실제 2.2.6 EXE --check-for-setup = 30(Pro 성공). 이어서 실제 설치를 금지한 Inno 테스트 실행에서도 인증 검사 = 30. 검사 후 실제 Windows 파일과 레지스트리 내용 일치. 설치는 수행하지 않음.

개발 시 주의: 이 Codex 프로세스에서 Production UsageQuota/설치 인증 검사/레지스트리 초기화를 직접 실행하지 말 것. 일반 Windows 컨텍스트에서 실행한 도구로 확인할 것. 테스트 빌드는 분리된 테스트 저장소를 사용. 복구 작업에 사용한 임시 예약 작업은 제거함.
