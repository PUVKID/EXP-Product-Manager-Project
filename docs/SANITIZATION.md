# 공개 사본의 연락처 비식별화

`Brand.cs` 12개의 연락 이메일 리터럴만 `CONTACT_EMAIL` 환경변수에서 읽는 같은 이름 `Email` 속성으로 바꿨습니다. 컴파일 상수는 실행 시 환경변수를 읽을 수 없으므로 이 필드만 속성으로 전환했습니다. 저작자·법적 귀속·제품·버전·다른 로직은 수정하지 않았습니다.

설정값이 없으면 `InvalidOperationException`으로 필요한 변수명을 알립니다. 본인의 공개 연락처를 프로세스 환경에 설정해야 하며 개인 연락처를 소스에 다시 넣지 마세요. 환경변수 읽기는 [Microsoft의 공식 API 문서](https://learn.microsoft.com/dotnet/api/system.environment.getenvironmentvariable)를 따릅니다.

실제 개인키 XML 14개 제외는 이전 사본과 동일하게 유지했습니다. 키를 요구하는 기존 발급 도구에는 별도 보관한 개인키가 필요합니다. 새 라이선스나 키를 발급하지 않았습니다.

## 2026-10-30 추가 공개 범위

22차와 21차 보관 2.2.5의 `Brand.Email`에도 같은 환경변수 규칙을 적용했습니다. 과거 설치 스크립트와 22차 설치 스크립트·도움말의 개인 연락처는 `contact@example.invalid`로 치환했습니다. 저작권·라이선스 문구의 저작자 연락처는 유지했습니다. 시험용 주소와 가상 키 예시는 실제 인증정보가 아닙니다. 빌드 스크립트와 설치 스크립트는 공개 입력으로 추가했으며 DLL·실행 파일·압축 파일·개인키·발급 이력·운영 데이터와 권리가 불명확한 바이너리 자산은 제외했습니다.

원본의 줄바꿈을 Git 인덱스에서 LF로 정규화하며, 공백 검사에서 확인된 일부 빌드·소스 파일의 마지막 빈 줄과 글꼴 라이선스의 두 행 끝 공백을 공개 사본에서 정리했습니다. 내용과 라이선스 문구는 유지했습니다.

과거 차수의 도움말·라이선스·manifest·시험 체크리스트를 추가하며 도움말에 포함된 개인 연락처도 같은 주소로 치환했습니다. 저작자 연락처와 라이선스 문구는 보존했습니다. 확인된 행 끝 공백과 끝 빈 줄은 공개 사본에서 정리했습니다. 22차 검증 도구와 원본 기준 해시를 그대로 보존했으며 공개 사본은 제외된 빌드 입력과 비식별화 때문에 원본 기준 검사를 반드시 통과하지 않습니다.
