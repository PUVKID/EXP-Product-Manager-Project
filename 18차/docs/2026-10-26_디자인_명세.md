# EXP 18차 디자인 명세와 구현 계획

## 요청과 확정 범위
2026-10-26 윤석님은 「🔄 모델 변경 EXE Project」의 플러그인과 제작 방법을 사용하되 외형은 다르게 만들라고 정정했습니다. 흑백·은색 첫 시안은 폐기된 방향이며 제품에 적용하지 않습니다. 이미지 시안 → 공통 디자인 규칙 → 기존 네이티브 앱 구현 → 실제 화면 비교와 독립 검증 순서로 진행합니다. 이 요청은 디자인 구현을 포함하며 기존 인증 초기화나 실등록 허가는 아닙니다.

## 채택한 디자인
- 사용자가 직접 선택한 오프화이트·잉크 네이비·코랄 포인트입니다. 라이트 #F7F8FA, 글자 #18243A, 포인트 #F47765; 다크 바탕 #111B2D/입력 #1C2B42. 코랄 위에는 충분한 대비의 어두운 글자를 사용합니다. 녹색 시안은 폐기된 방향입니다.
- 원형 링·금속 오브젝트·흑백 Orbit 배치를 복사하지 않습니다. 가로형 진행 표시, 읽기 쉬운 상품 목록, 넓은 편집 공간으로 구별합니다.
- 나눔고딕 Bold 700과 내장 폰트/OFL을 유지합니다. 라이트/다크/시스템 모드, 기존 메뉴 8개, Classic/Studio/Pro를 유지합니다.
- 대시보드는 큰 제목, 가로 통계, 현재 자동 등록과 기존 상태, 가로로 긴 최근 활동입니다. 8장의 균일한 카드 그리드를 반복하지 않습니다.
- 상품 입력·배송·예약·라이선스·자가진단·메시지·Master·Reset의 앱 소유 표면에 같은 색/여백/입력/버튼 체계를 적용합니다.
- 짧은 호버·선택·진행 모션은 상태 이해를 돕는 경우에만 사용합니다. 숨겨진/닫힌 화면에서 타이머를 정리하고 과한 장식 모션은 넣지 않습니다.
- 시안의 상품·숫자는 예시입니다. 실제 데이터로 대체하며 누적 성공을 오늘 성공으로 오인시키지 않습니다. 일일 사용량을 새로 읽기 위해 인증/사용량 쓰기 메서드를 추가 호출하지 않습니다.

## 기능과 안전 경계
기존 C# WinForms/.NET Framework 구조를 유지합니다. 웹 앱 전환은 기존 인증·TPM·Selenium 및 배포 환경 회귀를 늘리므로 하지 않습니다. Build Web Apps의 시안·디자인 체계·비교 방법을 네이티브 화면에 적용합니다. 웹 화면만 확인하고 EXE를 검증했다고 주장하지 않습니다.
등록·인증·TPM·라이선스 발급·일일 한도·시간 예약·저장 형식은 변경하지 않습니다. 지난 점검의 성공 판정/실패 집계 문제는 미수정 기존 이슈로 남기며 이번 디자인으로 해결됐다고 말하지 않습니다. 실제 앱 실행·인증·초기화·실등록·설치 교체를 수행하지 않습니다. UI 검사는 격리 TESTBUILD만 사용합니다. 사진 최대 12장, 배송 100~30000원 등 기존 검증을 보존합니다.

## 구현 순서와 소유권
1. build 작업자가 소스코드/src/Theme.cs, Design.cs, Brand.cs의 시각 부분, UI/Controls.cs, UI/FluentBox.cs, UI/UiKit.cs, UI/Pages 및 MainForm/EditForm/DiagnosticsForm의 시각 부분을 소유합니다. 관리자/초기화 도구는 시각 부분만 수정합니다. 다른 작업자가 바꾼 파일을 되돌리지 않습니다.
2. 공통 색·폰트·간격·버튼·입력을 먼저 정리하고 대시보드 구조를 바꿉니다. 기존 폼의 필드 이름/이벤트/검증 및 바인딩을 보존합니다. 기존 기능에 없는 임의 값·화면을 넣지 않습니다.
3. 격리된 RedesignUiTests를 추가해 메뉴/모드/핵심 화면/긴 문자열/작은 창/실제 모션과 Dispose를 검증하고 이미지를 생성합니다. 필요한 빌드 스크립트 변경은 build 담당입니다.
4. 기존 DpiLayoutTests를 100/125/150/175/200%에서 실행합니다. 카드 중첩·입력 수직 정렬·999 및 큰 반복 숫자·배송 입력/저장/취소 회귀를 유지합니다. 외형 변경으로 달라진 배치 기대는 명세 근거를 남기되 겹침/접근성 검사를 약화하지 않습니다.
5. main은 버전 2.3.0, 배포 패키지, 문서·상태 및 기본 로직 보존 해시를 소유합니다. 새 차수 18차만 수정하며 이전 차수를 보존합니다.
6. 별도 verifier는 동결 소스와 시안을 비교하고 실제 격리 검사 및 라우팅 명세를 실행합니다. 실패는 근거를 남기고 같은 작업에서 수리와 재검증합니다.

## 완료 기준
전체 주요 화면 라이트/다크 렌더, 기존 핵심 로직 해시 일치, 5개 DPI 배율, 독립 검사 통과, 사용자용 EXE/설치 파일과 관리자 도구 분리. 운영 데이터 접근·실제 다른 PC·실제 게시·장기 모션 안정성을 미검증 범위로 보고합니다.
