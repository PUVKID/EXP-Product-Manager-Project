# EXP 전체 목록 반복과 흑백 모션 재설계 구현 계획

2026-10-26 사용자 요청. 19차는 보존하고 20차, 버전 2.4.0으로 납품한다. 사용자용 결과는 이 폴더에만 저장한다. 기존 프로그램 실행·종료·설치·인증·초기화·상품 게시를 대신 수행하지 않는다.

## 요구와 선택

상품 관리의 유효한 전체 목록을 첫 회차 즉시 등록하고 이후 반복한다. 첫 회차에도 기존 등록 상품을 포함한다. 방식은 시작 시각 기준 N분 간격(1~1440분, 기본60), 또는 매시 M분(0~59, 기본0)이다. 15:02 시작 → 간격60이면16:02, 매시00이면16:00, 매시20이면15:20이다. 종료된 회차 이후에 다음 미래 슬롯을 선택해 지나간 회차를 몰아 실행하지 않는다. 동시에 두 회차를 실행하지 않는다. 빈 목록은 종료하고 실패를 조용히 무한 반복하지 않는다. 실제 게시 시 기존 보안·일일한도·Studio/Pro 반복권한을 유지한다. 중지·일시정지·서버시간 미확인·날짜 경계·설정 변경을 검사한다. 반복은 중지하거나 한도/인증으로 중단될 때까지 지속하고 기존 1개씩/시간대별/횟수반복 방식은 호환 유지한다.

내부 선택과 입력을 간결하게 바꾼다. 우선 예약에서 등록방식(한 번/1개씩/전체 목록 반복)과 반복시각(간격/매시 지정분)을 선택하고 필요한 입력만 표시한다. 실행 중에는 예약 설정을 변경할 수 없게 하거나 시작시 설정을 동결해 현재실행에 불일치가 없게 한다. 다음 시각과 반복 방식이 자동등록 화면에서 명확해야 한다.

최신 추가요청: 앱 전체 레이아웃·로고·작업표시줄 아이콘을 재설계한다. 기존 흑백·라이트/다크·나눔고딕Bold700 방향과 기능은 유지한다. Codex Orbit Project의 Product Design 및 Game Studio web-3d-asset-pipeline 지침을 참고해 실제 입체 자산과 적절한 전환·hover/press 모션을 쓴다. 텍스트/입력 위에 장식이 겹치면 안 된다. 애니메이션은 숨김·최소화·Dispose 때 멈추고 reduced motion 대응을 검토한다. 운영 PC에 새 GPU 서비스나 웹 서버를 상주시키지 않는다. PNG/ICO는 실제 자산의 모든표면 일치와 작은16/32px 가독성을 검사한다.

## 검증 범위와 근거

추가 부모 판정: 전체 목록 모드에서 로그인 실패·예외·시도 0건은 명시적으로 중단한다. 개별 상품 실패는 그 회차의 남은 상품을 처리한 뒤 실패 건수를 안내하고 반복을 중단한다. 기존 단일상품 모드 실패 정책은 이번 요구와 무관하게 변경하지 않는다.

19차 불변 baseline27개는 원본 그대로 보존한다. 이번 요구에서 변경이 필요한 Models/Runner/AutomationController만 사전 허용하며 그 외24개는 원래해시를 검증한다. 허용된3개는 새 동작검사와 독립코드검토로 검증한다. 검사기준을 현재해시로 갱신하지 않는다. 실제 상품게시/다른PC 인증/실운영 무오류는 주장하지 않는다.

Microsoft .NET Framework4.7.2 공식 Task.Delay 문서(https://learn.microsoft.com/en-US/dotnet/api/system.threading.tasks.task.delay?view=netframework-4.7.2)를 참고했다. 기존 UI Tick을 재사용해 별도겹침타이머를 추가하지 않는 방식을 우선한다.

설계안: 단일상품간격을60분으로 설정하는 방식은 전체목록반복 요구를 충족하지 못해 제외했다. OS예약프로그램은 앱인증/현재상태/중복실행을 별도관리하게 되어 제외했다. 기존Controller에 명시적목록회차모드를 추가하는 방식을 main이 선택했다. 사용자의 구현요청 및 반복승인생략 지침에 따라 별도 승인대기 없이 진행한다.
